# Agent-experience regression checks (2026-10-12)

The AX review used DevTool AX Kit at
`d9679c44cf2025b774b35f3223b9d58cb8f549e1` and compared the original `31185b1`
surfaces with the subsequent fixes. Three disposable local trials exercised CLI,
HTTP, and Python. A separate verifier process restarted each worker and inspected
restored files. These were scripted acceptance checks, not fresh-agent success
rates or a benchmark of model behavior.

| Check | Before | After |
| --- | --- | --- |
| Selected state restores after restart | 3/3 pass | 3/3 pass |
| Source fixture remains unchanged | 3/3 pass | 3/3 pass |
| CLI rejects unknown policy fields | 0/3 pass | 3/3 pass |
| Lost reset response can be reconciled | 0/3 pass | 3/3 pass with an operation ID |
| SDK exposes error request ID | 0/3 pass | 3/3 pass |
| Unknown API route has structured error | 0/3 pass | 3/3 pass |
| Required CLI inputs checked before network I/O | 0/3 pass | 3/3 pass |

The recovery trial deliberately drops the acknowledgement after a successful
reset. The fixed client retrieves the receipt and repeats the identical keyed
request; generation advances only once. This changes the recovery protocol by
using the new opt-in ID, not by introducing automatic retries. Unkeyed calls
retain their original unknown-outcome limitation.

Durable regression coverage lives in `engine/policy_test.go`,
`cmd/ramet/main_test.go`, `internal/server/operations_test.go`,
`internal/server/recovery_test.go`, and Python integration tests. Tests cover
pending/concurrent replay, body mismatch, session change, expiry during request
read, capacity rejection before effects, oversized/malformed results, and
structured routing/auth errors. Private captures and fixture hashes remain
outside tracked source.

Receipts are bounded, in-memory, and valid for one hour in the issuing API
session. This evidence does not establish recovery across worker restart or
worker-disk loss. The [agent guide](../agents.md) defines that boundary and the
application recovery requirements.
